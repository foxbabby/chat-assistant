# 聊天助手

基于本地 jev-jarvis 0.3.0 的 MIT 源码改造，保留并署名其微信窗口捕获、Vision OCR 和辅助功能输入实现。界面、云端调用、设置及自动回复控制已重新实现。仅支持 macOS 微信当前可见的文字聊天。

## 启动

双击 `start.command`，或运行 `uv sync --frozen && .venv/bin/python src/app.py`。需要 macOS 14 或更高版本、Python 3.12、uv；从源码构建还需要 Xcode Command Line Tools（swiftc）。首次安装需要联网下载 Python/框架绑定；没有 torch、transformers、laya、模型权重下载或本地大模型推理。

构建应用：`.venv/bin/python packaging/build_app.py`，结果位于 `dist/聊天助手.app`。应用使用独立虚拟环境，不依赖原版 jev-jarvis；构建包未做 Apple 公证，按构建机器的 CPU 架构生成。

## 使用

1. 点击设置，填写云端 API 地址、API Key、模型名称；默认 DeepSeek 地址 `https://api.deepseek.com`、模型 `deepseek-flash`。可填写基础地址、含 `/v1` 的地址或完整 `/chat/completions` 地址。
2. 点击测试连接后保存。配置保存在 `~/Library/Application Support/微信聊天助手/settings.json`（权限 0600）。密钥不会回传界面、写入日志或仓库；配置是仅当前用户可读的本地文件，并非加密钥匙串。
3. 在设置里允许辅助功能，随后重新打开助手。文字读取不再依赖截图或屏幕录制。
4. 选择一种回复风格；在微信打开目标聊天，点击开始监听，再保持微信在前台。
5. “自动回复”默认勾选：生成后自动发送到对应的微信或钉钉会话。取消勾选后，只生成内容（也不发送查询中的“稍等”提示），在回复工作台点击“发送”或“不发送”。微信、钉钉独立选择；暂停监听后可切换模式。新消息到达或暂停后，旧的待发送回复失效；发送前仍核对会话和消息，重复点击不会重复发送。
6. 设置“我的微信昵称／群昵称”和“无需回复的人员”，每行一个名称。仅当接口读到明确的发送者名称或会话名称时匹配；未知发送者不会阻止处理新消息。

仅处理开启后当前会话的新消息，不回复启动时已存在的消息。当前会话暂时无法识别、记录跳转、消息置信度低时保持监听；确定切换聊天时暂停，需要在新会话重新开启。编辑框已有内容、发送校验失败、网络/云端错误会暂停。更新回复设置保持监听；更换账号或监听对象时暂停对应会话。

发送前重新读取并核对会话、消息、前台应用、焦点、输入框；填入后定向发送一次 Return。要求微信的发送快捷键为 Return；若微信设置成 Command+Return，则不能确认发送，会暂停，不自动尝试第二种快捷键。发送后需要同时观察输入框清空及自己的新消息气泡，才显示“已发送并确认”。不确定时停止，不重试。去重指纹持久化于 `processed.json`，不包含原始聊天文字。

关闭窗口、退出应用或原生窗口进程异常结束都会停止自动回复，重新启动恢复各会话原来的监听状态和回复模式，不补发历史消息。当前会话最近 8 条文字会发给设置的云端服务；运行记录及消息正文只保留于进程内存。此工具不读取数据库、不注入微信、不修改原版安装。

## 验证与边界

运行 `.venv/bin/python -m unittest discover -s tests -v`。支持界面浏览验证：`.venv/bin/python src/server.py`，只监听 `127.0.0.1:18766`。桌面和浏览服务不可同时使用同一端口。

自动发送依赖辅助功能权限、当前微信会话和发送快捷键。非文字消息仅显示，不自动回复。源码测试不等同于真实微信发送验收。

### 系统已开启权限，助手仍显示未授权

本地开发版使用临时代码签名。原生启动器改动后，macOS 可能保留旧开关，但拒绝新版的代码身份。此时不要额外授权通用 Python：退出助手，在系统设置的辅助功能（新版 macOS 名为“设备控制和数据访问”）中移除旧“微信聊天助手”，重新添加当前 `dist/聊天助手.app` 并开启，再打开助手。后台实际访问通过才会显示已授权。

构建工具会复用未改动的原生启动器，避免 Python 和页面更新引起不必要的代码身份变化；原生启动器确实变化时仍可能需要重新授权。

助手发送前保存按会话与正文生成的哈希，24 小时内匹配的内容不再触发回复，记录在重启后保留；发送确认失败也不自动重试。相同会话内其他人发来完全相同的文字也会跳过。手工发送的消息若无发送者信息，仍可能被当作新消息处理。


### 个人表达与工作知识
设置中的“我的表达与工作知识”可维护口吻、本人真实表达示例和已确认知识。按当前相关片段送到所配置的云端，不自动将模型回复当作本人习惯。
SPD 相关问题按需只读查询指定钉钉账号的排查字典和现场群经验库，并检索本地 spd-lts 源码：供应商结账拆单按规则实现族及执行入口读取，需求计划按业务模块检索并区分普通查询、导入、补货入口，其他业务保留通用检索；不操作钉钉群消息、不改源码、不执行资料中的命令。字典不可用时记录警告，证据不足时，故障类问题先追问操作步骤、耗材编码或截图，不发送未确认的原因；其他无法确认的内容、图片识别失败或答案格式异常时，也会发送简短澄清追问。只有通过原有会话、身份、消息稳定性与发送校验的新消息才会发送；自己、排除人员、重复消息及无法确认发送结果的消息仍不会重复回复。本地源码不代表现场部署版本。此流程尚未接入所有测试用例空间、群历史或禅道实时状态，也不等于完整 Codex 技能运行环境。


### 表情图片与历史消息
- 主页面“开启时立即回复最后一条”默认关闭，勾选后当次开启才处理历史最后一条，仍走排除人员、稳定性复核和去重。
- 新收到的动画表情或图片可按描述和风格选择本地原创 PNG 表情卡片；无法看到图片本身时不猜其内容。图片不调用云端视觉模型，不联网下载随机素材。文件/通话等仍跳过。
- 图片发送临时使用剪贴板，发送流程结束时恢复；若用户期间复制了新内容则不覆盖。只发送一次，必须确认新图片消息及输入框清空。无法确认时保留待核实记录，不重发。
- 2026-09-22 已向用户明确授权的“文件传输助手”发送一张“收到”测试图片，程序确认和微信 AX 回读均通过。普通联系人、群聊和不同微信版本仍需实际观察。
- 学习档案为 Application Support/微信聊天助手/learned-profile.json；独立每小时学习任务更新，生成时重新读取，手动设置优先。不是实时覆盖全部历史，也不意味着拥有所有 Codex 技能。

发送准备完成后会自动将微信置前，再复核会话、消息和空输入框；空闲监听不切换窗口。切换联系人或未发送草稿仍会阻止发送。


## 微信与钉钉同时运行

主页左侧切换平台仅改变查看内容。两个平台拥有独立线程、状态与去重记录，分别点击开启／暂停。关闭 App 停止两边；重启后恢复退出前各会话的监听状态和自动／手动回复模式；已有消息不补发。

在设置中统一维护云端模型、风格、个人习惯、忽略人员、历史消息选项。钉钉：登录／重新授权 → 读取账号 → 连接并加载会话 → 选择一个监听会话 → 保存，然后切到钉钉开启。默认每 15 秒检查一次（10–300 秒），无新消息不调用模型。使用 ~/.local/bin/dws 和所选账号身份，不需要钉钉保持前台。发送采用引用回复，单次请求 + 幂等键 + 消息 ID 回读确认；未知结果暂停且不重发。钉钉图片／表情暂时使用文字回应，不猜测不可见图片内容。

微信仍监听当前打开的聊天：换联系人暂停微信，不影响钉钉。更新个人资料、回复规则、模型或风格时保持监听，只取消旧设置生成中的回复和待发送草稿；更换钉钉账号或监听对象时才暂停对应平台。

为保留旧版本的密钥、虚拟环境、学习任务路径和去重记录，内部数据目录继续使用 `~/Library/Application Support/微信聊天助手`；钉钉发送账本独立存放在其 `dingtalk/` 子目录。显示名称统一为“聊天助手”，Bundle ID 保留以兼容旧版授权。

开发启动：`./script/build_and_run.sh --verify`。原生名称变更会重新编译启动器，macOS 如拒绝旧授权，请在设置中重新添加当前 App。

## 原生辅助功能授权

设置中的“申请授权”通过受来源限制的 WKWebView 桥接，由原生 App 调用 `AXIsProcessTrustedWithOptions`，随后打开系统辅助功能设置页。后台 Python 不再发起授权提示。返回应用和打开设置期间自动检查原生权限；后台是否真正可访问仍由其实际权限状态判断。若原生已授权而后台尚未生效，页面提示退出重开，不将原生状态冒充后台可用。

旧版本曾与新版共用 Bundle ID，系统可能保留“微信聊天助手”的旧名称。旧应用已从 Launch Services 注销并保留在 artifacts/legacy-wechat-app.backup。若系统仍保留旧条目，移除旧的关闭条目后再由新版申请；macOS 可能要求用户进行触控 ID 验证。应用不自行打开开关或修改权限数据库。

## SPD 两阶段答疑与资料范围

识别到工作知识查询时，正式自动回复先向已校验会话发送“我查一下相关资料，稍等。”，再检索并回复。第二条仍需核对当前会话和消息；钉钉引用原问题并使用独立幂等键。资料或模型失败时发送澄清说明，暂停、切换会话、未知投递结果时停止发送，并在页面显示状态；进程中断后不会自动重发旧查询。预览和测试生成不发送消息。

本机私有文档索引位于 Application Support/微信聊天助手/spd-documents/index.json，已导入 SPD操作手册v5.24.0、新SPD功能业务测试用例和接口测试用例。索引是下载时的文本快照，未提取图片内容，也未执行测试用例。可通过 `uv run --with xlrd --no-project python script/index_spd_documents.py` 在重新下载资料后重建。文档不打包到 App、不进入公开仓库。

源码按业务模块和共享模型检索并标注本地提交版本，不能据此断言现场部署状态。SPD 测试库按本机 Navicat 已在使用的直连方式访问，使用固定 SQL、只读会话与短超时。答疑按主题读取少量表结构；消息明确给出耗材编码时，仅查询该编码在测试库的状态汇总，不读取整行记录或执行聊天消息中的 SQL。测试库结果不代表生产现场。连接凭据保存在本机受保护目录，不进入应用包或公开仓库；当前服务端未启用 TLS。

报错排查字典通过不带全文关键词的记录接口分页读取，在本地匹配问题，以避开上游关键词查询的序列化故障。单次最多10页、1000条，必须确认完整；仅在内存缓存120秒，缓存过期且读取失败时提示资料不可用，不静默沿用旧资料。读取始终校验工作账号；不会写入字典。

### 真实回复测试
“试试回复效果”使用已保存的云端模型、表达习惯和知识检索流程，展示模型名称、答案依据及检索提示。测试与实时消息使用相同的澄清回退：资料不足或模型无法提供依据时展示实际追问及原因，不将其标作有依据的业务答案；调用失败明确提示失败。此处按单条输入测试，不携带实时会话历史，也不发送消息。


### 钉钉多会话

主页选择钉钉后，点击会话列表旁的「管理」，可搜索并多选最多 12 个群聊或单聊。新增会话默认暂停、人工确认；选中会话后可独立开启监听，并选择是否自动回复或立即回复最后一条。切换查看不会改变监听与发送对象。暂停、移除、待发送回复、上下文、实时订阅和去重账本均按账号及会话隔离；移除仅取消本地监听，不退出钉钉群。来源和运行记录默认折叠。重启后逐会话恢复原来的监听／暂停状态及自动／手动回复模式，已有消息不补发；旧单会话配置及去重记录自动兼容。

钉钉历史消息仅作为可选上下文：启动时读取失败仍建立实时订阅，页面说明历史消息暂不可用，仅处理后续新消息，不执行“立即回复最后一条”。新消息正文直接来自限定会话的事件推送，发送结果按具体消息编号核验，不依赖历史列表恢复。身份、会话对象和实时订阅必须校验成功才显示监听就绪。临时连接准备失败保留开启意图及回复模式并延迟重试，手动暂停或移除可取消；账号、权限或订阅明确失败不自动重试。

## 本机工作资料配置

工作知识和测试库集成均为可选功能。账号、组织身份、文档节点、字典表、源码目录和数据库连接由 `~/Library/Application Support/微信聊天助手/work-settings.json` 提供，不写入 Git 仓库。该文件应设为仅本人可读（0600），数据库密码继续由独立的受保护 pgpass 文件管理。未配置的集成不可用，普通聊天不受影响。

支持字段：`knowledge_profile`、`knowledge_company`、`knowledge_user`、`experience_node`、`dictionary_base`、`dictionary_table`、`spd_root`、`spd_passfile`、`spd_connection`、`document_sources`。`document_sources` 是 `[本地文件名, 文档标题, 节点标识]` 的列表；不在代码中提供真实账号或资料标识。
